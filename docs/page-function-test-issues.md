# 页面功能测试问题文档

测试时间：2026-09-22（Asia/Shanghai）  
测试环境：本地开发页 `http://localhost:5173`，Chrome，已登录管理员账号

## 结论

核心页面流程基本可用，但发现 1 个明确功能缺陷：菜谱库的难度筛选选择“简单”后，结果仍包含“中等”菜谱。

修复状态：已修复并完成页面回归验证。

## 问题清单

### P1：难度筛选未真正过滤结果

- 页面：`/recipes`
- 影响：用户选择“简单”后仍会看到中等难度菜谱，筛选结果与筛选条件不一致，可能导致用户误选超出预期难度的菜谱。
- 前置条件：无

#### 复现步骤

1. 打开 `http://localhost:5173/recipes`。
2. 在搜索框输入 `虾`，点击“搜索”。
3. 打开“全部难度”下拉框，选择“简单”。
4. 检查结果卡片的难度标识。

#### 实际结果

下拉框显示“简单”且为选中状态，但结果仍包含以下 `medium` 菜谱：

- 西班牙海鲜饭：55 分钟 · medium
- 海鲜意大利面：35 分钟 · medium
- 鲜肉小馄饨：45 分钟 · medium
- 龙井虾仁：25 分钟 · medium

#### 预期结果

结果列表只应包含难度为 `easy`（页面中文显示“简单”）的菜谱；不应出现 `medium` 或 `hard` 菜谱。

#### 修复建议

- 检查难度下拉框的值是否正确映射到查询参数/筛选状态，例如 `easy`。
- 检查搜索结果计算逻辑是否实际使用了难度条件，而不是只更新了控件显示值。
- 为“搜索词 + 难度”组合增加回归测试，并断言结果中每条菜谱的 `difficulty` 都等于所选值。

#### 修复内容与验证

- 前端筛选下拉框在值变更时自动调用 `loadRecipes`，重新请求后端筛选结果。
- 难度、时间和分类筛选均采用同样的即时刷新行为。
- 复测“搜索 `虾` → 选择 `简单`”：结果只包含 `easy` 菜谱，未再出现 `medium` 或 `hard` 菜谱。
- `npm run build` 构建通过。

## 已验证通过的功能

- 首页及顶部导航：菜谱库、收藏、偏好、账户、管理端、基础数据入口可打开。
- 菜谱搜索：搜索 `虾` 可返回匹配结果。
- 菜谱详情：食材、制作步骤、小贴士、营养信息正常展示。
- 份量换算：2 人份增加到 3 人份时，食材数量同步换算；减少后可恢复。
- 收藏：详情页收藏状态可切换，收藏菜谱可在“我的收藏”中看到。
- 偏好：保存“喜欢的菜系”为“川菜”后出现“偏好已保存”提示。
- 管理端新增菜谱：空表单会触发“请填写此字段”的必填校验。
- 烹饪模式：可进入 `/recipes/107/cook`，步骤可从 1/3 切换到 2/3，上一步按钮状态正确变化。
- 菜谱深层链接：新标签页直接访问 `/recipes/107` 可正常渲染详情。

## 待复核观察

在原有标签页对详情页执行浏览器刷新后，曾出现页面短暂空白；随后在新标签页直接访问同一深层链接可以正常渲染。该现象未计入明确缺陷，建议修复难度筛选后补做“详情页刷新、前进/后退、深层链接直达”回归测试。
